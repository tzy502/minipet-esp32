## 新增需求 v1.0

### E1 — 服务端核心与素材导出（P0）✅ 已确认（2026-09-25）

把桌面版核心服务层（WZ 解析 / 纸娃娃合成 / 地图烘焙 / 气泡 / 曲库，共 10.4K 行）迁入本仓库 Server/，新增「布局导出器」：把纸娃娃部件导出为 RGB565 部件图 + origin，把每动作每帧导出为布局表（帧 × 部件 × x,y,z + expression 维度），把地图导出为静态背景双层烘焙（static_back + tile_layer）+ 视差条带元数据（偏移=f(time)）。

- 素材格式服务于设备端方案 C（部件图下发 + 设备端合成）
- 数据一切从 WZ 走，路径经配置注入（禁止硬编码）
- 表情按 25 个实证表情全量导出（expression 维度）
- 480 屏部件 1x + scale 2x nearest 由导出器标注
- 迁移时清理 17 处 Avalonia Dispatcher 引用（改普通回调/Channel）

### E2 — 设备协议（P0）✅ 已确认（2026-09-25）

服务端与 ESP32 之间的 HTTP 协议（设备永远是 client）。核心端点：

```
设备上线与素材
  POST /api/device/hello        设备注册：profile(w,h,shape,psram,audio) + UUID + 固件版本 → 返回 deviceId 与配置
  GET  /api/device/manifest     素材版本表（部件/布局/背景/字体/BGM 清单 + hash），设备 diff 后按需拉
  GET  /api/device/asset/{hash} 单个素材包（部件图/布局表/背景烘焙图）

指令与事件（长轮询）
  GET  /api/device/poll?since=  拉指令队列（切动作/表情/气泡文本/BGM 控制/亮度/重启），纯桌宠指令
  POST /api/device/event        设备上报事件（触摸/IMU 力度分级/倾斜角度/低电/错误）

BGM
  GET  /api/device/bgm/stream   MP3 流（服务端实时取链转发，设备只见此 URL）
  POST /api/device/bgm/cmd      播放/暂停/切歌/音量（设备端现场控制的回传）
```

- 协议里 **entities[]** 数组结构（首版 N=1，未来同屏多宠不改协议）
- **无 Hermes 字段、无 HA 字段**（隔离铁律）
- 无网络降级：所有端点不可达时设备用 TF 卡缓存独立运行
- 协议版本号字段预留（`proto`），v2 加东西不破坏 v1 设备

### E3 — 服务端部署与配置（P0）✅ 已确认（2026-09-25）

- **单容器**：api（ASP.NET Core 直接托管 Vue 产物 + API + BGM 流）；QQ 音乐网关 = 容器内 node 子进程（配置开关控制拉起，不启用则不存在）
- **对外唯一五位数端口 38090**（`.env` 的 `MINIPET_PORT` 可改），无 web 中间层
- **配置双通道**：Web 设置页与文本编辑写同一份 `data/config/appsettings.json`（WZ 路径 / 端口 / QQ cookie / 阈值），改后热重载（WzService 重新 LoadWz）
- **WZ 数据只读挂载**（NAS homes → 容器 `/wz`），开源用户路径自定义；仓库内禁止出现真实 IP/用户名（占位符）
- **镜像分发**：GitHub Actions 构建单镜像 → GHCR；备路 `scripts/deploy-nas.sh`（Mac buildx → save/load 直投 NAS）
- 验证清单随代码交付：SkiaSharp 容器内可用（fallback ImageSharp）、homes 挂载权限、双架构镜像

### E4 — Web 配置前端（P0）✅ 已确认（2026-09-25）

Vue 3 + Naive UI 管理界面（构建产物打进 api 镜像，单容器同源）：

- **设备卡片列表**（首页）：在线状态 / 当前宠物缩略图 / 换宠换装入口 / 配对码入册
- **素材浏览器**：地图 / 纸娃娃部件 / 怪物 NPC 浏览（服务端渲染缩略图）
- **纸娃娃编辑器**：换装组合 → 存为预设（供设备选择器「纸娃娃 tab」用）
- **曲库管理**：WZ 曲库浏览 + QQ 音源卡片（cookie 导入 / 有效期告警 / 启停开关）
- **设置页**：WZ 路径（含存在性校验）/ 端口 / 各阈值（IMU 灵敏度 / 死区 / 力度分级）——写 appsettings.json
- **表情入口**：25 表情手动指定（调试 + 演示用）
- 地图选择含**收藏**（喂给设备选择器的「最近+收藏」）

不做：设备端搜索输入、Web 点歌按钮（BGM 控制在设备上，已定稿）

### E5 — 设备端渲染与动画（P0）✅ 已确认（2026-09-25）

固件核心渲染能力（方案 C：部件图下发 + 设备端合成）：

- **部件合成**：按布局表（帧 × 部件 × x,y,z）在动作帧切换时合成一次，平时只 blit 合成结果；表情切换 = 只换 face 类部件重合成
- **动画时序**：按布局表 delay 序列推帧；动作播完回 stand（回退链）
- **缩放**：480 屏 1x 部件 + scale 2x nearest（像素风无损）
- **背景**：三层绘制——static_back → 视差条带（偏移=f(time) 或 IMU 倾角）→ tile_layer → 宠物 → 气泡
- **脏区上传**：只把变化区域推 QSPI（宠物区 30fps 局部刷新 ≤31% 带宽）
- **blink 本地循环**：随机 3~8s 播 blink，断网也眨眼（生命感地基）
- **动画铁律**：只播服务端下发的布局表（源头是 WZ 真实 action），固件不自创任何动画

### E6 — 设备交互：触摸 / 重力 / 力度 / 按键（P0）✅ 已确认（2026-09-25）

**通用按键模型（跨设备通用的最小交集，胶水定稿）**

单一职责，不绑具体引脚：
- **任何可用物理键（≥1 个）= 「菜单键」**：呼出/收起设备选择器
  - 主力板 = GPIO18；其他设备（冰箱贴等）映射到自己的键；无键设备退化为主屏角落常驻小按钮（触摸）
- **菜单 = 独立全屏窗口（胶水补充定稿）**：菜单打开时是一个独立界面（全屏覆盖层），宠物本体与触摸交互完全隐藏/冻结——菜单内所有触摸都归菜单，不穿透、不误触宠物；关闭菜单 = 恢复宠物态。彻底避免「菜单和宠物抢触摸区」的冲突
- 键位映射表在固件 profile 里定义，Web 可改键

**触摸（全部走屏，不占键）**
- 宠物交互：轻点 = 抚摸（smile/love）
- **BGM 播放控制 = 触摸**：BGM 控制层（半屏控制条：播放/暂停/切歌/音量），由选择器内 BGM 入口或宠物区长按呼出

**重力感应（IMU）**
- 左右倾斜（超阈值）→ 背景视差条带反向平移（背景动、人不动）+ 人物原地 walk1
- 上倾 → 人物切 fly；回正 → stand
- 死区 ±8°、保持 300ms 防抖；角度 100ms 上报（服务端重算 layout 下发）

**力度分级（IMU 加速度，设备端算好只上报事件）**
- 轻拍 <2g → alert + bewildered；大力拍打 ≥4g → hit 表情；剧烈摇晃 → stunned；拿起/翻转 → fly + oops

阈值全部 Web 可配（与 E4 设置页同一份配置）。
（主力板具体三键的额外分工——PWR 切时钟态、BOOT 调试——留到固件 profile 阶段细化，不进通用需求）

### E7 — 设备选择器（控制中心）（P0）✅ 已确认（2026-09-25）

菜单键呼出的**独立全屏窗口**（E6 定义的形态，与宠物本体隔离），三个 tab：

- **地图**：列表由后端返回（预设+最近+收藏）；后端不可用 → 只显本地缓存项；缩略图 64×64 服务端渲染；`cached` 标记服务端算；选中 → 素材未缓存则拉包落 TF 卡（1~2s）→ 切换
- **纸娃娃**：预设列表（Web 编辑器存的）+ 最近使用；换装 = 拉差量部件包
- **怪物/NPC**：同上（预设 + 最近）
- 切换完成后宠物反应 = **随机表情**
- 素材落 TF 卡：切过的秒切；淘汰策略 = 保留最近 N 个 + 收藏
- 窗口内含 **BGM 入口**（呼出 E6 的触摸控制条）
- 第 4 个 tab「家居」（HA 面板）为 **P2 预留位**，一期不实现

### E8 — BGM 子系统（P0）✅ 已确认（2026-09-25）

双源流式音乐，控制权在设备：

- **音源**：WZ 曲库（默认）+ QQ 音乐（可选，`IMusicSource` 可插拔）——**不同类型源**，设备上先选类型，之后切歌/上下曲/随机**只在所选类型内**转换
- **QQ 接入**：容器内 node 子进程（Rain120 网关）；只锁 128k 明文 MP3；vkey 短时效由服务端实时取链转发（直链不下发设备）；cookie Web 导入+过期告警；**该源可整体停用**
- **短路规则**：失败只在**同源内**重试降级（跳下一首/重试取链），**禁止跨源自动换歌**；某源整体不可用 → 设备该源入口**置灰**，手动切类型才换源；failover 事件上报 + 宠物 `despair` 表情
- **控制入口**：设备触摸（E7 菜单内 BGM 入口 → 半屏控制条：播放/暂停/切歌/音量），Web 只管曲库/歌单/cookie
- **播放**：设备 HTTP 流式拉取 → minimp3 解码 → I2S 出声；断网 = 静音降级（不做本地曲库缓存）
- 音量/当前源偏好存设备配置（服务端设备表同步）

### E9 — 时间功能（P0）✅ 已确认（2026-09-25，地图时钟位置=魔法值+Web可配）

- **待机时钟**：无人交互 N 分钟 → 宠物睡眠态 + WZ 数字时钟浮现（fontTime：AM/PM + HH:MM，起点 = clock+(18+3,83)，AMPM_GAP=12px，comma 偶显奇隐，12h 制、午夜 AM 00:xx）；AMOLED 纯黑背景只数字发光（省电）
- **时间源**：PCF85063 RTC——配网时 NTP 校准一次，断网独立走时
- **地图时钟（胶水修订）**：设备端**不解析 WZ clock 配置**——地图时钟的显示位置作为**魔法值写死在固件配置**（一组「地图模板 → 时钟坐标」的固定表），由 Web 配置页可改；后续开发中再按实测逐图校准固化。理由：26 张地图的 clock 坐标是 WZ 数据细节，设备端零 WZ 解析（隔离铁律），位置由服务端下发布局时附带或固件配置表提供
  - 附图例参考（胶水 2026-09-25 截图）：时钟显示框是地图上的绿边深棕底长条矩形（如藤蔓拱门上的空白牌）——固定位置即对准此类牌子
- 交互（触摸/按键/IMU）→ 立即唤醒回桌宠态
- 番茄钟/倒计时系：不做（已砍）

### E10 — 表情系统（P0）✅ 已确认（2026-09-25，与 E9 同批确认）

25 个实证表情的完整落地：

- **触发型**：播完自动回 default；触发映射按 E6（触摸/力度/系统事件）
- **blink**：设备本地随机 3~8s 循环（E5 已含）
- **系统事件映射**：BGM 播放=hum / 低电=despair / 配对成功=cheers / 素材故障=dam / 过温=hot
- **随机轮播**：静置时低频播稀有表情（wink/chu/qBlue）
- 表情切换 = 只重合成 face 类部件（E5 已含，快）
- **来源约束**：25 表情之外不做任何自创表情；某表情素材缺失 → 回退 default（导出器保证）

### E11 — 降级与容错（P0）✅ 已确认（2026-09-25，OTA 修订：直接 WiFi 升级）

- **无网络**：WiFi 不可达/服务端掉线 → 用 TF 卡缓存素材独立运行（宠物照常动、blink 照常眨）；BGM 静音降级；选择器只显本地缓存项；**回到网络自动重连并同步**（manifest 补拉）
- **服务端重启/升级**：设备端长轮询指数退避重连（1s→2s→…→60s 封顶），期间本地模式
- **素材包损坏**：hash 校验失败 → 弃用重拉；宠物播 dam 表情提示
- **TF 卡满**：按淘汰策略清（保最近 N + 收藏）
- **低电分级**：<20% 宠物打哈欠（troubled）→ <10% 强制睡眠保电（纯时钟态）
- **OTA（胶水修订）**：**设备直接走 WiFi OTA**——服务端下发升级指令（poll 指令含固件版本与下载地址），设备从服务端 HTTP 拉固件包自更新；双分区 + 失败自动回滚旧分区；**不需要插线烧录**
- 所有降级事件上报服务端（Web 可见设备健康状态）
